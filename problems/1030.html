#1030

집합과 쿼리 2

난이도 3 ⏱ 2.000s 🧠 512 MB
정렬 이분 탐색 쿼리형 문제

문제

원소가 모두 양의 정수인 집합 $U$ $=$ {$e_1, e_2, ... , e_N$} 가 주어진다.

아래 쿼리를 수행하는 프로그램을 작성해보자.

  • $k$ : 집합 $U$에 정수 $k$가 속해 있다면 $1$, 속해있지 않다면 $0$을 출력한다. $(1 ≤ k ≤ 10^9)$

입력

첫째 줄에 집합의 크기 $N$과 쿼리의 개수 $Q$가 공백으로 구분되어 주어진다. $(1 ≤ N, Q ≤ 200,000)$

둘째 줄에 $e_1, e_2, ... , e_N$이 공백으로 구분되어 주어진다. $(1 ≤ e_i ≤ 10^9)$

셋째 줄부터 $Q$개의 줄에 걸쳐 쿼리가 주어진다.

출력

각 쿼리가 주어질 때마다 그에 맞는 정답을 차례대로 출력한다.

예제

예제 입력
5 3

1 2 3 4 5

3

7

1
예제 출력
1

0

1

💎 힌트 아이템

AlgoWiki의 인벤토리·아이템 시스템으로 잠금 해제되던 프리미엄 힌트입니다.

집합의 크기와 쿼리의 개수가 최대 $200,000$까지 될 수 있다. 이에 따라 쿼리 당 약 $O(logN)$ 수준으로 응답할 수 있어야 한다.

크게 두 가지 방식을 떠올려볼 수 있다.

  • 집합 내 요소가 바뀌지 않음에 따라, 정렬 후 이분 탐색
    • 정렬에 $O(NlogN)$, 쿼리 당 $O(logN)$으로 $O((N+Q)logN)$에 문제를 해결할 수 있다.
  • tree / hash 기반 자료 구조 사용
    • tree
      • $N$개의 원소 삽입에 $O(NlogN)$, 쿼리 당 $O(logN)$으로 $O((N+Q)logN)$에 문제를 해결할 수 있다.
    • hash
      • $N$개의 원소 삽입에 $O(N)$, 쿼리 당 $O(1)$로 $O(N+Q)$에 문제를 해결할 수 있다.
      • 해시 충돌을 생각하지 않았을 때 기준이며, 만약 해시 충돌을 고려한다면 $O(N(N+Q))$의 시간 복잡도를 갖게 된다.
