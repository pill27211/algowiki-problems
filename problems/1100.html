#1100

집합과 쿼리 5

난이도 9 ⏱ 2.000s 🧠 512 MB
자료 구조 세그먼트 트리 좌표 압축 트리를 사용한 집합과 맵

문제

집합 $U$ = { ∅ }에 대해 아래의 쿼리를 수행하는 프로그램을 작성해보자.

  • $1$ $k$ : 집합 $U$에 $k$를 추가한다. $k$가 이미 $U$에 속한다면 아무것도 수행하지 않는다.
  • $2$ $k$ : 집합 $U$에서 $k$를 제거한다. $k$가 $U$에 존재하지 않는다면 아무것도 수행하지 않는다.
  • $3$ $l$ $r$ : $l ≤ x ≤ r$ 이고 $x∈U$ 인 $x$의 개수를 출력한다.
모든 쿼리에서 $k, l, r$은 정수이며, $(-10^9 ≤ k, l, r ≤ 10^9; l ≤ r)$를 만족한다.

입력

첫째 줄에 쿼리의 개수 $Q$가 주어진다. $(1 ≤ Q ≤ 200,000)$

둘째 줄부터 $Q$개의 줄에 걸쳐 임의의 쿼리가 주어진다.

출력

$3$번 쿼리가 주어질 때마다 그에 맞는 정답을 차례대로 출력한다.

예제

예제 입력
9

1 1

3 2 5

1 5

2 2

3 3 6

1 3

3 1 5

1 1

3 1 2
예제 출력
0

1

3

1

💎 힌트 아이템

AlgoWiki의 인벤토리·아이템 시스템으로 잠금 해제되던 프리미엄 힌트입니다.
1. 좌표 압축 + 세그먼트 트리
$k, l, r$의 범위로 세그먼트 트리의 할당 범위를 특정하기 다소 난감할 수 있는데, $(1 ≤ Q ≤ 200,000)$ 임을 생각해보자.
수의 범위에 비해 실제로 등장하는 수의 개수는 생각보다 적음을 알 수 있다. 이는 곧, 좌표 압축을 통해 수의 범위를 좁혀줄 수 있음을 의미한다. 쿼리를 모두 받아놓고, 등장하는 수들의 범위를 줄여주자.
이후 문제는 간단한 $Point$ $Update$ $Range$ $Query$로 바뀌고 세그먼트 트리를 이용해 각 쿼리를 $O(logQ)$에 쉽게 처리할 수 있게 된다.
정렬 역시 $O(QlogQ)$이므로, 문제를 총 $O(QlogQ)$에 해결할 수 있다.
2. $PBDS$ $(Policy$ $Based$ $Data$ $Structure)$
이 자료 구조는 $ordered$_$set$으로, 기본적인 $set$의 특성에서 여러가지 연산을 추가적으로 지원한다.
C++의 경우 GNU C++의 확장 라이브러리에서 이를 지원하며, 여기 Algowiki에서의 채점 환경에서 역시 이를 지원한다.
이 자료 구조를 이용할 경우 온라인으로 쿼리를 처리할 수 있다. 주로 사용할 연산은 다음과 같다. 

order_of_key(k) : k보다 앞선 우선순위를 갖는 원소의 개수
이 연산을 이용하면 $3$번 쿼리는 곧 다음으로 변환된다. 

order_of_key(r + 1) - order_of_key(l)
상수가 조금 붙지만 $set$의 특성 상 연산 당 $O(logQ)$의 시간 복잡도를 갖으므로 총 $O(QlogQ)$에 문제를 해결할 수 있다.
