문제

친구의 친구는 친구다.

$1, 2, ... , N$의 번호가 고유하게 매겨진 $N$명의 사람이 있다. $i$번 사람은 $i$의 키를 갖는다. 아래의 쿼리를 수행하는 프로그램을 작성해보자.

  • $1$ $a$ $b$ : $a$번 사람과 $b$번 사람이 친구가 된다. $(1 ≤ a, b ≤ N; a ≠ b)$
  • $2$ $a$ : $a$ 및 $a$와 친구인 사람의 수를 출력한다. $(1 ≤ a ≤ N)$
  • $3$ $a$ : $a$ 및 $a$와 친구인 사람들 중에서 $a$의 키가 몇 번째로 큰지 출력한다. $(1 ≤ a ≤ N)$

내 친구의 친구는 나와 친구이기 때문에, $1$번 사람과 $2$번 사람이 친구이고 $2$번 사람과 $3$번 사람이 친구라면 $1$번 사람과 $3$번 사람도 친구이다.

입력

첫째 줄에 사람의 수 $N$과 쿼리의 수 $Q$가 공백으로 구분되어 주어진다. $(2 ≤ N ≤ 100,000; 1 ≤ Q ≤ 200,000)$

둘째 줄부터 $Q$개의 줄에 걸쳐 임의의 쿼리가 주어진다.

입력으로 주어지는 모든 수는 정수이다.

출력

출력을 요구하는 쿼리가 주어질 때마다 그에 맞는 정답을 차례대로 출력한다.

통상적으로 분리 집합에서는 집합 별 대표 노드를 관리할 뿐 집합마다 속해 있는 실제 원소를 계속 들고 다니지는 않는다.
그러나 본 문제에서는 특정 요소에 대해 해당 요소가 속한 집합에서의 우선순위까지 판단해낼 수 있어야 한다. 즉, 실제 집합을 들고 있어야 한다.
문제의 제한을 확인하자. 집합의 $merge$를 단순하게 수행한다면 메모리 초과던 시간 초과던 맞기 십상일 것 같다.

결론부터 말하자면 $Small$ $To$ $Large$라는 테크닉을 사용해 효율적으로 이를 수행할 수 있다. 항상 작은 쪽에서 큰 쪽으로 집합을 전이하면 작은 쪽의 입장에서 봤을 때 집합의 크기가 적어도 $2$배 이상 증가함에 따라, 각 원소 역시 최대 $O(logN)$번만 이동하게 된다.
이 간단한 기준을 추가해줌으로써 최악의 경우 전체 $O(N^2)$번의 원소 전이가 무려 $O(NlogN)$번으로 줄어들게 된다.

한편, 우리는 여전히 다음 문제를 해결해야 한다. 

특정 집합에 속한 k가 해당 집합에서 몇 번째의 우선순위를 갖는가?
일반적으로 우리가 사용하는 $set$에서는 전체 원소의 상대적인 우선순위를 유지할 뿐, 특정 원소의 우선순위를 구하는 연산은 지원하지 않는다.
$PBDS($$Policy$ $Based$ $Data$ $Structure$$)$라는 자료구조가 있다. 이 자료구조는 $Ordered$_$Set$으로, 기본적인 $set$의 기능에 추가적인 연산을 지원한다. 주로 쓰이는 기능은 다음과 같다. 

find_by_order(k) : k번째 우선순위를 갖는 원소의 위치 정보

order_of_key(k) : k보다 앞선 우선순위를 갖는 원소의 개수
C++의 경우 GNU C++의 확장 라이브러리에서 이를 지원하며, 여기 Algowiki에서의 채점 환경에서 역시 이를 지원한다.

지금까지 정리한 정보를 이용한다면 $O(NlogN)$번의 원소 이동에 대해 각 원소 이동마다 $log(N)$의 연산을 소모하므로, $O(Nlog^2N)$에 문제를 해결할 수 있다.
